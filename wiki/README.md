# wiki

A deterministic, no-LLM-at-generation-time wiki compiler. It turns a folder
of source files (`.txt`, `.md`/`.markdown`, and `.rs`/`.py`/`.js`/`.ts`/`.go`/
`.cpp`/`.cc`/`.cxx`/`.h`/`.hpp`/`.hh`/`.hxx` code) into a cross-linked Markdown wiki plus
machine-readable artifacts (`index.json`, `llms.txt`, `AGENTS.md`) built *for*
LLM/agent consumption — no model call happens during compilation, and output
is byte-identical across runs and machines.

## Install & build

```bash
cargo build --release
```

The binary is written to `target/release/wiki`. For local runs without a
separate build step, use `cargo run --release -- <args>` in place of the
binary path.

Pushing a `v*` tag runs the release workflow, which builds Linux x86_64 and
macOS (Apple silicon and Intel) binaries and attaches them to the GitHub
Release for that tag.

## Quickstart

Run from `wiki/`:

```bash
cargo build --release
./target/release/wiki generate demo_raw --files 12 --seed 42
./target/release/wiki compile demo_raw demo_wiki --incremental --emit-json
./target/release/wiki search gradient --dir demo_wiki
./target/release/wiki neighbors gradient_descent --depth 1 --max-tokens 800 --dir demo_wiki
./target/release/wiki lint --dir demo_wiki
```

## Opening the wiki in Obsidian

Per-page cross-links are Obsidian-flavored wikilinks with an explicit slug
target: `[[slug|Display Name]]` (e.g. `[[gradient_descent|Gradient Descent]]`).
Each `<slug>.md` file is a real page in the output directory, so the links
resolve directly — no plugin or extra configuration needed.

To browse a compiled wiki in Obsidian, open the **output directory itself**
(e.g. `demo_wiki/`) as the vault root — not a parent directory that might
also contain the raw input sources, since those can have basenames that
collide with the generated pages. With the output directory as the vault
root, the graph view and backlinks panel work immediately.

The same `[[slug|Name]]` format is also **Quartz-compatible**: Quartz parses
Obsidian-flavored wikilinks natively, so a compiled wiki's Markdown can be
dropped into a Quartz `content/` directory and its links will resolve. This
does *not* mean `wiki compile` produces a Quartz site — Quartz is a separate
npm-based static site generator you set up yourself; `wiki` only guarantees
that the Markdown it emits is link-compatible with it.

### Slugs

Page ids (and filenames) are slugs matching `[a-z0-9_]+`, derived from each
source name by folding punctuation, whitespace, and non-ASCII characters
down to `_`/ASCII in a single pass. Two names that differ only by
punctuation or whitespace (e.g. "Fetch (v2)" vs "Fetch v2", both → `fetch_v2`)
can slugify to the same id, as can two files with the same stem in
different directories, or a header and its implementation file
(`orderbook.h` + `orderbook.cpp`). Disambiguation is total — no source file
is ever dropped for a name collision — via a three-rung escalation ladder,
described in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md#disambiguation-ladder):
directory-segment qualification, then a filename discriminator, then a
free-id search that cannot fail. A `mod.rs` or `__init__.py` page is named
after its directory (`tests/common/mod.rs` → `common`), since that is the
name every importer uses. A name that is
**entirely** non-ASCII (no `[a-zA-Z0-9]` survives the fold) has no
meaningful ASCII slug to derive, so it becomes an anonymous `page_<hash>`
file instead — transliteration (e.g. Cyrillic → Latin) is not performed.

## CLI reference

Every subcommand also accepts the global options below.

### `compile`

```
wiki compile [OPTIONS] <INPUT> <OUTPUT>
```

- `--incremental` (off) — reuse `.wiki/cache.json` render fingerprints and skip unchanged pages.
- `--no-ignore` (off) — do not apply `.gitignore`/`.ignore`/hidden-file rules while walking `<INPUT>`.
- `--emit-json` (off) — also write `graph.json` (node/edge graph).
- `--project <NAME>` (the input directory's basename) — project name written to `index.json`, `llms.txt`, and `AGENTS.md`. Without it, `compile .` and `compile "$PWD"` name the project differently.
- `--memory <local|DIR>` (none) — also compile an agent memory folder as flagged memory pages: `local` for this repo's per-user folder, or a directory. `<INPUT>/.agents/memory` is always compiled. Without a resolvable folder it warns on stderr and continues.
- `--watch` (off) — one-shot compile, then keep watching `<INPUT>` and recompile on change. Events are debounced for 150 ms and events under `<OUTPUT>` are ignored; each run reports `recompiled: N pages (M written)` on stderr.

If `<OUTPUT>` still holds pages written under a previous id scheme (an
earlier compiler version, or sources renamed since), `compile` warns
`warning: N page(s) from a previous id scheme remain in <OUTPUT> …` on stderr
and leaves them in place — delete them or recompile into a clean directory.

### `search`

```
wiki search [OPTIONS] [QUERY]
```

- `--kind <k>` (none — all kinds) — filter by kind: `code` (every `code:<lang>`), `docs` (`markdown` and `text`), or one exact `SourceKind`: `text`, `markdown`, `code:<lang>` (e.g. `code:rust`). Memory notes pass both `code` and `docs`.
- `--tag <tag>` — only pages carrying this tag (`#` and case ignored; `a` also matches `a/b`). With no query, lists every such page by path. A query or `--tag` is required.
- `--limit <N>` (`10` with a query; none for a bare `--tag`) — maximum number of hits returned.
- `--format <lines|json>` (`lines`) — output shape, below.
- `--dir <out>` (`out`) — the compiled wiki directory to read.

The default `lines` output is one line per page, `id  path  [date  ]title — summary` (the date is the page's `updated`, shown when known).
Under a code page, up to 3 indented lines name its matching symbols,
`  path:start-end  name  signature  — doc` (1-based, inclusive line range;
`name` is `Owner::name` for methods; `doc` is left out when empty or already
shown on an earlier line of the page). Only symbols scoring at least 30% of
the best symbol in the response are shown, and test code ranks at half score.
A page without symbol lines gets its body snippet on a four-space-indented
line instead, with comment markers (`//`, `///`, `#`, …) dropped. A C++
declaration that declares several names shows one signature per name, which
may not appear verbatim in the file. `--format json` prints
`[{id, title, summary, updated, score, snippet, path, symbols}]` (`updated` only when the page's date is known), where each symbol is
`{path, start_line, end_line, name, signature, doc}`.

### `neighbors`

```
wiki neighbors [OPTIONS] <ID>
```

`<ID>` is a page id, or anything that names exactly one page: its title (any case), a slug of a title, or a source path or unique path suffix (e.g. `query.rs`). It resolves like `page`, so an absolute path under the compiled directory works too. If nothing matches, the error lists the closest ids.

- `--depth <N>` (`1`) — BFS hop count from `<ID>`; with `--symbol`, how many calls deep (no limit by default).
- `--max-tokens <N>` (none — unbounded) — hard ceiling on the pack's estimated size (chars/4). A code target is its outline, cut to fit; another target that alone exceeds it degrades to a title + summary block pointing at the full page.
- `--max-nodes <N>` (none — unbounded) — node-count budget for the returned context pack.
- `--full` (off) — include whole neighbor outlines (code) and page bodies (other pages) instead of one-line summaries. Without it, the modules the target imports or is imported by come first, as outlines when they fit.
- `--kind <KIND>` (none) — only neighbors of this kind, with the values of `search --kind`.
- `--symbol <NAME>` (none) — a function on the page (`name` or `Owner::name`): print every function it calls instead, through all levels (or `--depth` of them), one `start-end  kind  Owner::name` line each, grouped by file. Calls are matched by name, so a method called on a value can list every same-named method the caller's file sees.
- `--dir <out>` (`out`) — the compiled wiki directory to read.

### `page`

```
wiki page [OPTIONS] <ID>
```

Prints a page's outline: for a code page one line per symbol, so you can read
just those lines of the source instead of the whole file. `<ID>` resolves like
`neighbors`, and an absolute path under the compiled directory works too: it
must pass through that directory's name (`root` in `index.json`).

- `--full` (off) — print the whole page instead of the outline.
- `--max-tokens <N>` (none — unbounded) — ceiling on the output's estimated size (chars/4).
- `--dir <out>` (`out`) — the compiled wiki directory to read.

```
# Lib (lib)
src/lib.rs  code:rust
Adds numbers.
imports:
  std::fmt
4-5  fn  pub fn add()  — Adds.
7-7  type  pub struct G
G:
  9-10  method  pub fn build(&self)  — Builds.
  11-11  method  fn helper(&self)
14-18  module [test]  mod tests
16-17  fn [test]  fn adds()
```

Item lines are `start-end  kind  signature`, then `  → twin` for a paired C++
declaration or definition and `  — doc` when there is a doc sentence. Methods
sit under an `owner:` line. Test items carry `[test]`. A markdown page lists
its `headings:`, a text page only the header. A code page compiled before
`items.json` existed prints `no items — recompile with a current wiki for
symbol lines`.

When `--max-tokens` is smaller than the outline, parts are cut in this order
until it fits: test items (not on a page that is all tests), then docs, then
imports, then trailing items. A last line says what went:
`… dropped: 3 test items, 5 docs — pass max_tokens: 2412 for all`, or
`… 12 more items from line 140 — pass max_tokens: …` when trailing items were
cut (`N more headings` on a markdown page). The header, the marker and, on a
code page without items, the `no items` line are never cut, so a tiny budget
can still be exceeded by them.

With `--full` and `--max-tokens` below the page's size, a code page with
items prints `full page ~N tokens exceeds max_tokens; outline follows` and
then its budgeted outline; any other page is cut after whole lines, ending
with `… truncated at ~B of ~N tokens`.

### `lint`

```
wiki lint [OPTIONS]
```

- `--dir <out>` (`out`) — the compiled wiki directory to check for broken links, orphan pages and pages too large for a default `neighbors` pack.

Prints the counts, then one `  broken: <page> -> "<link>"`, `  orphan: <id>` or
`  large: <id> (<n> tokens)` line per offender. A page is large when it is over
4000 tokens with the pack separator, so `neighbors` would degrade it to a
summary; code pages are not checked. `[[links]]` inside fenced blocks or
inline code are not counted, and the `## Body` of a code page is skipped
entirely: it is verbatim source, where a wikilink is a string literal or a
comment, not a link. Exits 1 when any broken link is found, so `lint` can
gate a build; orphans alone exit 0.

### `serve`

```
wiki serve [OPTIONS]
```

- `--source <project>` — also compile this project and keep the wiki in step
  with it (see [MCP server](#mcp-server)).
- `--dir <out>` (`<project>/.wiki` with `--source`, else `out`) — the
  compiled wiki directory to serve.
- `--tools <list>` (`search,page,neighbors`) — the tools to expose,
  comma-separated, from `search`, `page`, `neighbors`, `lint`.
- `--memory <none|DIR>` — with `--source`, `none` leaves out this repo's local
  agent memory folder and `DIR` replaces it; a `DIR` that does not exist at
  start is not watched (the next start picks it up).

Runs an MCP (Model Context Protocol) server over stdio for the compiled
wiki. See [MCP server](#mcp-server).

### `hint`

```
wiki hint [OPTIONS] [TEXT]
```

Prints the code locations for a task text: the text agents' hooks inject
before the agent starts reading. A header line, then at most 8
`path:start-end  name  signature` lines (each cut at 160 characters) from
the best-matching code pages, at most 2 per page; docs, test items and a
line whose range holds another of the page's lines (a class around its
methods) never appear. Prints nothing and exits 0
when the wiki is missing or unreadable, or nothing matches, so a hook can
run it on every prompt.

- `--dir <wiki>` (`.wiki`; with `--claude-hook` and `CLAUDE_PROJECT_DIR` set,
  `$CLAUDE_PROJECT_DIR/.wiki`) — the compiled wiki directory.
- `--claude-hook` — read a Claude Code `UserPromptSubmit` hook's JSON from
  stdin and use its `prompt` instead of `TEXT`. Without it, `TEXT` is required.

### `setup`

```
wiki setup [--agent claude,pi] [--scope repo|local] [--hook] [--remove]
```

Run in the project root. Compiles `.` into `.wiki`, then installs what makes
Claude Code and pi use the wiki on their own: the MCP server (`wiki serve
--source .`) and a `wiki-navigation` skill. Agents are detected (`.claude/`,
`CLAUDE.md` or `claude` on `PATH`; `.pi/` or `pi` on `PATH`) unless
`--agent` names them.

- `--scope repo` — committed files for the whole team: `.mcp.json`,
  `.pi/mcp.json`, `.claude/skills/wiki-navigation/SKILL.md`,
  `.agents/skills/wiki-navigation/SKILL.md`, and `.wiki/` in `.gitignore`.
  `wiki` must be on `PATH`; setup warns when it is not.
- `--scope local` — this checkout only (also written as `wiki`, with the same
  warning; a file git already tracks is skipped, use `--scope repo` for it): Claude Code's server goes through
  `claude mcp add-json wiki … --scope local`, the other files are written and
  listed in `.git/info/exclude`.
- Without `--scope`, setup asks on a terminal and fails without one.
- `--remove` deletes exactly what setup wrote, hooks included even without
  `--hook`. Ignore lines and `.wiki/` stay.
- `--hook` — also adds the wiki's code lines for each prompt before the model
  runs. Claude Code gets a `UserPromptSubmit` entry (`wiki hint --claude-hook`)
  in `.claude/settings.json` (`settings.local.json` with `--scope local`);
  pi gets `.pi/extensions/wiki-hint/index.ts`. The hook is silent when there
  is no wiki, it cannot be read or nothing matches, and never blocks a prompt.

A JSON config setup edits is rewritten as 2-space pretty JSON (keys and their
order kept), so a hand-formatted file comes back reformatted after install or
`--remove`.

Safe to run twice. An entry or file at the same place with other content is
left alone and reported; setup does the rest and exits 1. pi loads project
files only after you trust the project (`/trust`, or `--approve` in print
mode).

### `generate`

```
wiki generate [OPTIONS] <DIR>
```

Synthetic corpus generator, useful for demos and reproducing bug reports.

- `--files <N>` (`20`) — number of source files to write into `<DIR>`.
- `--seed <N>` (`42`) — SplitMix64 seed; same seed + `--files` always produces byte-identical output.

### Global options

- `--jobs <N>` (none — Rayon default, usually the number of CPUs) — worker thread count for `compile`. Output is byte-identical regardless of the value (see [Determinism](#determinism)).

## Using the wiki from an agent

A compiled wiki is meant to be read by an agent instead of re-crawling the
source tree. Four artifacts drive that:

- **`index.json`** — the machine catalog. Top level is `{ project, root, entries: [...] }`,
  where `root` is the compiled directory's own name (even for `compile .`);
  each entry has: `id`, `title`, `kind`, `aliases`, `tags`, `updated` (present only when the page has a date), `path`, `page`, `summary`
  (`null` when none could be derived — a code file with no doc comment and
  no exported item), `degree_in`, `degree_out`, `pagerank`, `token_estimate`,
  `neighbors_out`, `neighbors_in` (edge targets and sources; what makes an
  edge is described under [Limitations & roadmap](#limitations--roadmap)),
  `imports_out`, `imports_in` (the import edges among them; a page's
  `## Imported by` section lists `imports_in`, `## Mentioned in` the rest of
  `neighbors_in`),
  `defined` (the page's top-level definition names —
  functions, types, constants — in original case; empty for non-code pages),
  `methods` (the page's inherent-impl and trait-declaration method names, in
  original case; trait-impl methods are excluded; empty for non-code pages).
- **`items.json`** — the code map, kept out of `index.json` so the catalog
  stays small. One compact object keyed by page id (code pages with at
  least one item); each value lists the page's items — its top-level items
  and methods — with `kind`, `name`, `owner`, `signature`, original
  `start_line`/`end_line` (so an agent can read just those lines), `doc`,
  `public` flag, for a paired C++ declaration or definition `twin`, and
  for a function `calls` (the `path:start-end` of the functions it calls).
- **`llms.txt`** — a compact, human- and LLM-readable index with one-line
  summaries, meant to be pasted into a prompt or skimmed cheaply. Pages at
  or above the median PageRank go under `## Docs`, the rest under
  `## Optional`.
- **`AGENTS.md`** — a short usage guide written into every compiled wiki,
  telling an agent where to start (`index.md`/`index.json`), how to fetch a
  neighborhood (`wiki neighbors <id> --depth N`), how to get a module's
  symbol map (`wiki page <id>`) and where line ranges live (`items.json`),
  and that the `## Notes`
  section of each page is preserved across recompiles.

The agent workflow is search → page → read lines: `search` finds the page,
`page` lists its symbols with line ranges, and the agent reads just those
lines of the source file with its own file tool. `neighbors` is for when the
surrounding pages matter.

### The `neighbors` context-pack workflow

`wiki neighbors <id>` builds a budgeted context pack for an agent:

1. BFS outward from `<id>` up to `--depth` hops.
2. `--max-tokens` is a hard ceiling on the pack's estimated size; `--max-nodes`
   caps the node count, dropping the lowest-centrality neighbors first. Under
   `--max-tokens`, neighbors are admitted in descending centrality,
   skip-not-break: one that doesn't fit the remaining budget is skipped and
   the walk continues, so the kept set favors high-centrality neighbors over
   maximum cardinality.
3. Neighbors are ordered by centrality (PageRank), **highest last**, so the
   most important context sits closest to the end of the pack.
4. The target page (`<id>`) comes first — in full when it fits the budget,
   otherwise as a title + summary block with a pointer to `wiki://page/<id>`,
   so the neighborhood still fits.
5. `--full` includes full neighbor page bodies instead of one-line summaries
   (larger pack, more token cost).

Real invocation and (trimmed) output:

```
$ ./target/release/wiki neighbors gradient_descent --depth 1 --max-tokens 800 --dir demo_wiki
# Gradient Descent
…
## Layer Normalization (layer_normalization)
Layer Normalization builds directly on the ideas behind Gradient Descent.

## Learning Rate Schedule (learning_rate_schedule)

```

## Using the wiki as agent memory

An agent can keep its notes as markdown files in a folder the wiki compiles,
then `search` them before it writes. `wiki setup` creates the folder and tells
the agent about it in the skill it writes:

- **Repo scope** (`--scope repo`): `.agents/memory/` in the project. It is
  committed, so everyone with the repo sees the notes. `wiki compile` always
  includes it.
- **Local scope** (`--scope local`): a folder outside the checkout, in the
  per-user data dir: `%LOCALAPPDATA%\wiki\memory\<key>` on Windows,
  `~/Library/Application Support/wiki/memory/<key>` on macOS,
  `$XDG_DATA_HOME` (else `~/.local/share`)`/wiki/memory/<key>` elsewhere.
  `<key>` is the repo's root commit, so every worktree and clone of one repo
  shares it. Nothing backs it up, and it survives `git clean`. A directory
  that is not a git repo has no local memory.

`serve --source` and `wiki setup` include the local folder automatically. A
plain `wiki compile . out` does not (so a published site never carries private
notes); pass `--memory local` for it, or `--memory DIR` for any folder. A plain
`wiki compile . .wiki` therefore drops local memory from `.wiki` until the
server recompiles, and `wiki hint` reads `.wiki`. `wiki setup --remove` never
deletes notes.

Memory pages rank above code (their score is multiplied by 4), pass the
`code` and `docs` filters of `search`, and are found by the same tools as any
page. When a prompt names a note in its title, an alias or its summary,
`wiki hint` adds one `memory: <path> — <summary>` line to its code lines;
the line needs a prompt word of six or more characters in that match, or a
word of four or five characters while the note scores at least twice the best
code page (before the memory boost).

A note can retire an older one with `supersedes:` in its front matter (a list
of titles, aliases or ids, in `aliases:` syntax). The older note then gets no
boost and no memory-first tie order, `search` prints ` (superseded by <id>)`
after its line (`"superseded_by"` in JSON), and `wiki hint` never shows it. Only
memory notes are matched, a name that matches nothing is ignored, and with
several superseders the smallest id is shown.

The skill carries these rules; copy them into the agent's instructions file
if it has no skill:

```
Memory notes live in <folder> (.agents/memory, or the local folder setup named), one markdown file per fact or topic.
- Keep a note under about 16,000 characters (`wiki lint` reports `large` above that).
- Name the file for what it says. The title is the front-matter `title:`,
  else the first `# heading`, else the file name; any script works.
- A note not written in English needs English `aliases:`: agents search in English.
- Front matter, all optional: `title:`, `description:` (one line, the search
  summary), `aliases:`, `tags:`, `updated: YYYY-MM-DD` (date of the last change; other formats are
  ignored).
- A journal note is named `YYYY-MM-DD.md` and has the date in its H1.
- Mention a related note by its exact title or alias, or as `[[title]]`.
- Search before writing. Update the note that exists instead of adding a copy.
- When a decision changes, update its note. If you write a new note instead, add `supersedes: <old note's title>` to it.
- `MEMORY.md` is optional and is not searched.
```

Cyrillic query words are stemmed, so another grammatical form of a word still
matches, and a Cyrillic title gets a transliterated id (`Морський маяк`
becomes `morskyi_maiak`). See [`docs/KNOWN_GAPS.md`](docs/KNOWN_GAPS.md)
for the limits.

## MCP server

Or run `wiki setup` in the project: it writes this configuration (and a skill) for Claude Code and pi.

`wiki serve` exposes a compiled wiki to MCP clients (Claude Code, Claude
Desktop, and other agents) over stdio — the native alternative to shelling
out to the CLI. Client configuration:

```json
{
  "mcpServers": {
    "wiki": { "command": "wiki", "args": ["serve", "--dir", "demo_wiki"] }
  }
}
```

**Tools** (mirroring the CLI subcommands, with two differences: `neighbors`
and the `page` outline default `max_tokens` to 4000 here, where the CLI leaves
it unbounded, and `search` defaults `limit` to 5, where the CLI returns 10 —
an agent calling with defaults should not receive a 30 KB dump, and every hit
line is re-read on each later turn, while a person passes the flag on purpose;
`page` with `full: true` has no default). `lint` is exposed only when
`--tools` names it: it serves the person keeping the wiki, and each exposed
tool costs schema tokens on every request.

| Tool | Parameters | Returns |
|---|---|---|
| `search` | `query` (empty with `tag` lists the tagged pages), `tag?`, `kind?` (`code`, `docs`, `text`, `markdown`, `code:<lang>`), `limit?` (5 with a query; none for a tag-only listing), `format?` (`lines`, default, or `json`) | The `lines` text described under `search`, or with `json` `[{id, title, summary, updated, score, snippet, path, symbols}]` (`updated` only when known; `snippet` is `null` for title/alias/summary/heading-only hits) |
| `neighbors` | `id` (id, title, or path), `depth?` (1), `max_tokens?` (4000), `max_nodes?`, `full?`, `kind?`, `symbol?` | The context-pack text, or with `symbol` the functions it calls |
| `page` | `id` (id, title, or path), `full?` (false), `max_tokens?` (4000 for the outline) | The outline text, or the whole page |
| `lint` (with `--tools`) | — | JSON `{total_pages, broken_links, orphans, large}` |

**Resources:** every page is `wiki://page/<id>` (markdown), plus
`wiki://index` (`index.json`) and `wiki://llms.txt`.

**Freshness:** without `--source`, the server checks `index.json`'s
fingerprint before each request and reloads if the wiki was recompiled — no
restart needed. If a reload fails (e.g. mid-compile), the previous snapshot
keeps serving and the reload is retried on the next request.

**With `--source <project>`** the server compiles the project itself. An
existing wiki is served at once while the compile runs in the background; with
none, the first compile runs before serving and a failure exits. It then
watches the project and recompiles incrementally on edits (ignored paths such
as `target/`, build dirs and `.git` never trigger it). Each tool call waits up
to 5 s until edits made before it are compiled. If a recompile fails or is
still running, the last good snapshot keeps serving and tool results and
resource reads gain a line `wiki may be stale: <reason>`. Short-lived barrier
files, one per call, live in `<dir>/.serve/`.

Without `--source` the server only reads the wiki. The CLI `search`,
`neighbors` and `lint` never recompile; they read the wiki as it is.

## Library usage (Rust)

`wiki` is also usable as a library — the CLI is a thin wrapper over the same
API:

```rust
use std::path::Path;
use wiki::{compile, CompileOptions};
use wiki::query::{Wiki, PackBudget};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let opts = CompileOptions { incremental: true, ..Default::default() };
    let result = compile(Path::new("demo_raw"), Path::new("demo_wiki"), &opts)?;
    println!("{} pages compiled", result.pages_total);

    let wiki = Wiki::load(Path::new("demo_wiki"))?;
    for hit in wiki.search("gradient", None, 5) {
        println!("{}\t{}", hit.id, hit.title);
    }
    let budget = PackBudget { max_tokens: Some(2000), ..Default::default() };
    if let Some(pack) = wiki.neighbors("some_id", 1, &budget) {
        println!("{}", pack.text);
    }
    Ok(())
}
```

`CompileOptions.project` (the CLI's `--project`) sets the project name written to `index.json`,
`llms.txt`, and `AGENTS.md`; it defaults to the input directory's basename.
Besides `search` and `neighbors`, `Wiki` exposes `page(id)` (a rendered
page's Markdown), `has_page(id)`, and `list_pages()` (`(id, title)` pairs,
ascending by id) — the same calls the MCP server's resources use.

## Determinism

Compiling the same input twice — on any machine, with any `--jobs` value —
produces byte-identical output. This holds across the ordering of parallel
work, hashing, float comparisons, and path handling. See
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for the specific rules that
make this guarantee hold.

## Limitations & roadmap

Deliberate scope cuts, recorded so they read as decisions rather than
oversights. Measured shortfalls and agent behaviour are listed in
[`docs/KNOWN_GAPS.md`](docs/KNOWN_GAPS.md).

- **Linking is lexical.** No LLM, embeddings, or semantic matching at
  generation time. A text or markdown page is linked when a name or alias
  of it appears in another page. A code page is linked only by a
  code-shaped mention of its module — a `::` path (`text::extract`,
  `use crate::text::X`), a `mod text;` declaration, or its filename
  (`src/text.rs`) — by an import whose path names its module or one of
  its definitions, or by a relative markdown link (`[text](../other.md)`)
  resolving to its source path. Plain prose and a bare `` `text` `` do not
  link a code page: a one-word module name would otherwise draw an edge
  from every English use of the word. This is the core design trade-off,
  not a bug.
- **Call chains are resolved by name.** `neighbors --symbol` follows
  call edges matched by name at compile time, within one language, with
  no type information and no callers query. Code extraction is
  imports + exported signatures plus each function's line range,
  with Rust signatures owner-qualified
  (`pub fn Wiki::search(…)`, `fn <X as Trait>::method(…)`) and Python
  signatures owner-qualified through the full class chain and carrying
  their decorators (`def Article.Inner.deep(self) -> None`,
  `@dataclass(frozen=True) class Article`). A Rust `const`/`static` or a
  Python assignment keeps its value up to 48 chars (`pub const LIMIT: u32 =
  5`, `MAX_IDS = 2000`); beyond that a typed binding drops the value and an
  unannotated Python assignment truncates it with `…`. `#[cfg(test)]`
  modules are omitted from `## Body` and replaced with a
  `// [tests omitted: …]` marker.
- **Markdown front matter** may carry `aliases:` and `tags:`, written `a, b`, `[a, b]` or a YAML block list (`key:` then `  - a` lines). Tags are lowercased with any `#` stripped, and show on the page and in `index.json`. A markdown page's date is read from `updated`, `modified` or `date`, then the same keys in a `metadata:` block one level deep, then a file name starting `YYYY-MM-DD`; the value's leading `YYYY-MM-DD` is kept.
- **Text, markdown, and code are the only formats.** There is no PDF,
  OCR, or audio extractor; adding one means adding an `Extractor` (see
  [ARCHITECTURE.md](docs/ARCHITECTURE.md)).
- **MCP server is query-only.** `wiki serve` exposes search/neighbors/page
  (lint on request) and page resources over stdio (see [MCP server](#mcp-server)); there is
  deliberately no compile-over-MCP tool (`--source` recompiles on file edits,
  not on request) and no HTTP transport.
- **Graph export is JSON only.** `--emit-json` writes the node-link
  `graph.json`; there is no DOT/GraphML export.
- **`--watch` covers `compile` only.** The query subcommands (`search`,
  `neighbors`, `page`, `lint`) have no watch mode.
